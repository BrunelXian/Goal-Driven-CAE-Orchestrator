# VeriCAE 0.5.6 — Adaptive Agent Model Assignment

这是Main的简短配置/判断协议，不是决策引擎、预算数据库或第二Runtime。
保持四个持久角色、同项目绑定、Main单写者、真实跨对话来源与授权、短回执及原生通信纪律。
实际默认值见 [静态模型策略](model-policy.yaml)，不能把策略文件的请求值当成已生效配置。

## 当前核验的模型目录与默认请求

2026-11-23通过当前Codex原生模型目录核实以下ID及对应推理强度：

| 长期角色 | 模型家族 | 实际模型ID | 原生thinking值 |
|---|---|---|---|
| Main | Astra | `gpt-6.2-astra` | `high` |
| CAE | Luna | `gpt-6-luna` | `medium` |
| Results | Luna | `gpt-6-luna` | `medium` |
| Independent Validation | Sol | `gpt-6.2-sol` | `high` |

这些是本机当次目录中可见且支持所需强度的同家族当前优先项，不是对其他宿主永久可用的承诺。
每次初始化先查当前实际可用目录及支持的effort，匹配完整ID与强度；不从Astra/Luna/Sol简称
猜测ID，不把CLI枚举thinking选项当成每个模型都支持，不静默替换代际、家族或推理强度。
目录/目标ID/强度不可核实时报告 `MODEL_ASSIGNMENT_UNAVAILABLE`，说明缺项及最小人工操作。
不要求用户安装开发CLI、Python或Node来查目录；用宿主实际可用目录/模型选择器，查不到则如实限制。

## Initiate：创建、复用与实际生效核验

1. 按长期角色协议先查找复用，仅创建缺失角色。不为改变模型删除或重建已有线程。
2. 创建新长期对话时，先核对原生工具真实schema是否支持模型与Thinking；例如当前create_thread
   使用 `model` 与 `thinking`。若宿主参数名不同，只使用实际支持的对应项，不猜参数名。
3. 明确传入对应完整模型ID与强度，连同实际Project ID、准确角色标题和本轮已确认的创建范围。
   不省略这两项而默认继承Main模型，也不把写在创建提示中的模型名称当成真正设置。
4. 创建返回真实线程身份后，核验实际生效的模型和Thinking。优先读取宿主返回/原生配置元数据；
   另核对该目标真实运行轮次的配置（若宿主可提供），区分线程默认与本轮临时覆盖。
   仅请求参数、创建成功、目录支持、角色自述或静态TOML都不能证明生效。
5. 在Handoff/Task Cards现有正文中分别记录：期望值、实际请求、实际观测值、真实Thread引用、
   核验来源/时间、状态及限制；实际未回读时写NOT_VERIFIED，不复制期望值到实际列。
6. 工具不支持自动设置、请求被拒绝、实际配置不符或无法自动核验时，报告
   `MODEL_ASSIGNMENT_UNAVAILABLE`并说明具体范围（例如“可请求但缺实际配置回读”）。
   指出最小操作：用户打开指定既有线程，选择准确模型和Thinking，再核对实际值；不假装已自动完成。
7. 复用线程时先观察现配置；与默认不同只报告差异并提出变更，不静默覆盖。
   需要升级/调整时由Main明确提出并记录理由、旧值/新值、用户允许的变更范围；
   通过宿主实际配置能力或用户界面操作后再次核验才生效。没有可靠设置/回读入口就保留原配置并报告限制。
   不能只为设置模型发送空白/虚构科研任务，不能在文件或内部数据库中伪造生效状态。

## 新增专业Agent前的Role Capability Assessment

Main先做简短评估，不默认创建第五个角色：

- **必要性**：现有Main/CAE/Results/Independent Validation能否完成；若足够则复用，不新增。
- **任务类别**：常规明确执行、复杂工程分析/程序排障、高难度科学探索或重大科研决策。
- **错误后果与独立性**：误判影响、是否需独立核查、工具/文件访问需求和禁止操作。
- **资源适配**：预计任务持续时间、模型成本层级、输入/输出上下文需求和实际目录能力。

默认选择可靠完成任务的最低成本模型；可靠度、独立性和上下文适配优先于廉价。
一般候选：常规Luna/medium；复杂工程Sol/medium或high；科学探索/重大决策Astra/high；
高风险独立核查至少评估Sol/high是否足够，必要时提议Astra/high。
候选仍需当前目录支持；失败不静默回退。任务类别不是自动分类程序，不按关键词盲目分配。
目录没有报价时实际价格/总费用写UNKNOWN，不编造数字；成本层级仅是策略默认，必要时核实实际成本。
按当前目录检查上下文容量，不假定更高成本模型一定有更长上下文；超限先提出有来源的输入整理方案。

仅在现有Task Card/日志正文记录几行：是否新增/复用、任务类型与风险、工具/独立性、预计时长/上下文、
完整候选ID/Thinking和简短理由/未知项。创建新Agent仍须真实人类创建授权与原生身份/可见性核验。
该评估不签发执行授权、不新增复杂状态服务，不修改研究目标或模型资格。

## 跨对话模型保持与显式升级

普通Main→角色派发及角色→Main回发均**省略model和thinking参数本身**，不传null、空串、
Main的值或策略默认值；让已有目标配置保持。当前发送工具声明省略这两项会保留目标设置，
但真实模型保持必须以实际异模型发送前后测试确认，不能依据本Skill或工具说明直接判PASS。
例如Astra/high Main发送到Luna/medium CAE，核对目标线程配置及实际执行轮次前后均一致；
再测Sol/high独立核查角色。只测试同模型互发不能排除隐性继承。

单个任务复杂不自动改变长期线程配置。需要升级时Main先明确提案/记录并获得适用变更授权，
在真实工具支持时显式设置，实际验证后才报告生效。未经授权的覆盖、观测不符或未知继承
应停止继续分派并报告；不自动改回、删除或重建线程，不覆盖历史证据。
没有真实前后观测时模型保持写NOT_RUN/NOT_VERIFIED，不能借0.5.4通信已通过推定此项通过。

普通长期Thread的模型参数与可选Subagent TOML的model/model_reasoning_effort是不同配置面。
三个可选TOML保持不固定模型，不能用改TOML冒充普通线程配置；临时Agent也须另做必要性评估及实际配置核验。
