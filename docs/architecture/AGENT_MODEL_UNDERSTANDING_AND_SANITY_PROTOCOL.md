# GD-CAE Agent 模型理解与 Sanity Model 工作规范

**读者：** Main、专业 Agent、独立审查 Agent，以及模型检查与执行工具的开发者。  
**文档状态：** 拟采用的行为规范与验证设计；不构成现有产品功能、运行状态或测试通过声明。  
**研究依据核查日期：** 2026-11-04。  
**配套用户说明：** [Sanity Model 用户指南](../user/SANITY_MODEL_USER_GUIDE.md)。

本仓库已有 ResearchProject 与 Goal、Model、Verification 合同的持久化机制。[现有合同与存储边界](M02_RESEARCH_PROJECT_AND_CONTRACTS.md)给出实现入口与权威分工。本协议中的能力分级、验证建议和用户界面应按各自里程碑验收。

本规范记录 GD-CAE 的模型理解原则、证据要求和建议工作流程。它不定义新的运行时 API、强制状态机或首版交付范围。只有在项目明确采纳并提供相应执行能力后，相关规则才成为实际工作流程的一部分。

本文本身不授予模型或系统操作权限。实际执行应依据当前任务授权与项目配置：只读任务不得因本规范描述了建模、导出或求解流程而扩大范围；已授权的研究任务则可按相应预算开展建模与验证。采用本规范也不自动要求修改现有 GD-CAE 架构。

## 1. 定义与适用范围

### 1.1 Sanity Model

在 GD-CAE 中，**Sanity Model 是具有明确身份、可检查的工程定义、可追溯的依据，并已取得指定研究用途资格的基准模型**。资格必须注明适用的物理假设、参数范围、工况、评价指标和证据限制。

这个定义是 GD-CAE 的项目约定，不是 Abaqus 官方对象名称或通行行业认证。

基准可以由研究者提供，也可以由 Agent 建立。两种来源采用相同的资格原则；模型创建者的身份不代替模型证据。尚未通过所需验证的模型称为“候选基准”，不应借用 Sanity Model 的名称暗示其已经适合正式科研推断。

Sanity Model 提供一个具体的工程对象，使后续研究能够回答：

- 本次候选从哪个基准产生？
- 哪些物理定义保持一致，哪些研究变量发生改变？
- 观察到的响应差异是否来自计划中的实验变化？
- 原有验证证据对本次候选仍然有效到什么范围？

### 1.2 Verified-Model-First

本规范将 Verified-Model-First 解释为：**在使用模型支持正式研究结论之前，先取得与该结论相匹配的模型资格。**

它允许 Agent 先自主建模、诊断、试算和改进候选，再通过相应检查取得资格。它不要求研究者在所有任务开始前提供一个人工作成的 `.cae`，也不要求探索性候选从第一次创建起就可靠。

候选基准可以在明确的资格验证或探索预算内进行已授权计算。资格门槛约束正式研究接受和结论使用，不应被实现成“未经求解验证就不许进行验证求解”的循环阻断。

探索工作可以失败。系统应保留失败的输入、观察、诊断和可恢复状态，避免把“得到结果”“正常结束”或“拟合较好”自动提升为科研接受结论。

### 1.3 资格针对主张成立

模型资格至少要回答“用于什么”。以下主张需要不同证据：

| 主张 | 典型证据 | 不能据此直接推出 |
| --- | --- | --- |
| 定义与目标实验一致 | 几何、材料、夹持、加载、观测位置的核对 | 数值误差足够小 |
| 数值解可信 | 适当的解析基准、网格/时间步研究、平衡或能量检查 | 真实实验被准确代表 |
| 响应与实验一致 | 独立实验数据、误差标准、工况与测量定义 | 反演参数具有唯一性或可辨识性 |
| 支持材料反演 | 响应验证、参数化正确性、敏感性及混淆因素分析 | 所有参数区间和新工况均适用 |
| 支持候选排序 | 指标定义正确、比较条件一致、排序稳定性证据 | 最优候选适合所有其他目标 |

采用何种验证深度，应由具体研究用途、误差容许和决策后果决定。不得宣称存在对所有 CAE 模型都充分的固定验证清单。

## 2. Codex 理解模型的技术机制

Codex 的文件、Shell 和工具调用能力提供访问工程软件的通道。受支持的 `.cae` 理解路径通常为：由 Abaqus/CAE 内核打开 MDB，脚本读取对象和关联，Agent 根据结构化事实解释工程含义，再由独立依据检查关键解释。[O1][O2][A1][A2]

需要分别报告四种情况：

| 证据类别 | 可使用的表述 | 不应使用的表述 |
| --- | --- | --- |
| 官方机制支持 | 官方提供相应 API 或命令 | 因此本项目已经正确实现 |
| 代码中存在实现 | 已定位实现、输入假设和检查逻辑 | 因此该代码本次运行成功 |
| 技术方案待验证 | 已提出可实施的提取或修改方案 | 已具备可靠通用能力 |
| 本轮实测通过 | 明确版本、样本、环境、检查及结果 | 对任意复杂模型都可靠 |

本研究未发现足以证明 Codex 已原生提供完整 `.cae` 语义解析器的官方资料。也未发现可以替代 CAE 内核的、受厂商支持的完整普通 Python `.cae` reader。这个检索结论不等于独立解析在理论上不可能。

### 2.1 文件的不同证据作用

| 文件 | 主要用途 | 理解与取证边界 |
| --- | --- | --- |
| `.cae` | 持久保存模型和作业；可能保留原生几何、特征、网格与分析定义 | 专用数据库；导入几何或孤立网格本来就可能没有原始参数化历史；外部依赖不一定嵌入 |
| `.inp` | 表达求解器输入模型及分析历史 | 不保存 MDB 全部信息；不能无损恢复草图、原生特征与完整参数依赖；还须解析包含文件和执行依赖 |
| `.jnl` | 原生 Journal 可记录用于重建保存数据库的命令 | 应核对内容、版本和依赖；扩展名不能证明文件是有效 Journal；静态读取不等于执行安全 |
| `.rpy` / `.rec` | 会话重放线索 / 最后保存后的数据库更改线索 | 历史记录不能直接代替当前保存状态；可能含文件写入、提交或其他动作 |
| `.odb` | 已保存的模型信息、分析结果及有关诊断 | 不代替完整 MDB；输出请求、实际输出和研究指标必须分别核实 |

官方明确提醒：INP 不能保存全部 MDB 数据，不能作为 MDB 归档替代品。导回的 Parts 主要以网格形式恢复，不支持的关键字或数据可能被忽略。因此，“INP 可作为合法执行输入”和“INP 可以无损恢复 CAE”必须分别判断。[A3][A4][A5]

### 2.2 无 Abaqus 环境中的判断边界

只有 `.cae` 时，可检查文件身份、字节、来源和可见版本线索；不能将少量可打印字符串作为完整对象读取结果。

如果同时提供 INP、脚本或先前导出报告，可分析其中真实包含的定义。必须标明证据来自哪个文件，不能把读取 INP 或复述项目说明称为“从 `.cae` 自主理解成功”。

## 3. L0—L5 能力分级

此分级用于组织任务证据，不是模型厂商评级，也不是已测得的准确率。能够生成复杂脚本不证明同时取得其他等级；应逐项记录哪些能力已验证。

| 等级 | 能力 | 达成条件 | 常见误判 |
| --- | --- | --- | --- |
| L0 | 文件识别与来源核对 | 文件可定位；记录版本线索、哈希、来源和有关依赖 | 扩展名正确即认为内容有效 |
| L1 | 定义读取 | 目标范围内的对象、值、成员和缺项准确提取 | 对象名称清单等于完整读取 |
| L2 | 关系重建 | 重建目标 Job/Model、材料赋值、区域、约束、接触、输出及有效步状态 | 仅检查创建时参数，忽略传播、失活和局部坐标系 |
| L3 | 工程解释 | 事实支撑角色和含义解释；未知及替代解释明确 | 读出定义即声称理解作者设计意图 |
| L4 | 受控候选生成 | 参数映射正确；只改变允许项；在声明覆盖范围内验证不变量和版本关系 | 文件保存成功即认为修改正确 |
| L5 | 指定用途的研究资格 | 独立验证支持指定主张，适用范围和限制清楚 | 求解成功、曲线吻合或多 Agent 同意等于资格完备 |

### 3.1 三种运行环境的能力矩阵

下表表示技术条件，不保证具体部署已经提供这些工具。第三种环境必须具有真实、经过测试的控制与验证实现，名称本身不会增加可靠性。

| 能力 | 只有 Codex，没有 Abaqus | Codex + 本机 Abaqus 2024 + API | Codex + GD-CAE Core + AbqJobPilot + 独立验证 |
| --- | --- | --- | --- |
| L0：来源与文件识别 | 可做文件和文本检查 | 可进一步用内核检查能否打开 | 可统一来源、依赖和运行记录 |
| L1：读取 `.cae` 定义 | 仅 `.cae` 不足；已有文本导出可辅助 | 官方机制支持，实际覆盖率待测 | 可通过版本化提取工具稳定提供 |
| L2：关系与有效状态 | 受提供证据限制 | 可实现，但需针对复杂对象测试 | 可建立缺项、冲突和覆盖检查 |
| L3：物理与研究含义 | 依赖可见事实和工程上下文 | 增加直接事实，不自动补全设计意图 | 可结合任务合同、外部依据和独立审查 |
| L4：原生 CAE 候选 | 可以写脚本，不能验证内核执行结果 | 可原生修改、保存、批量生成 | 可增加变更约束、预算及证据准入 |
| L5：研究资格 | 可做部分理论核查，无法完成本机求解验证 | 可开展适当验证，须另行组织依据和证据链 | 可形成受控科研闭环，仍需充分验证依据 |

Codex 的具体版本、模型、推理设置、可用工具、上下文和任务预算均可能影响表现。不得从一个案例通过推导通用准确率。

## 4. 确定性事实、推断、未知与建议

每个关键结论应属于下面一种类别：

| 类别 | 内容要求 | 示例 |
| --- | --- | --- |
| 事实 | 原值、单位声明来源、对象路径或文件位置、提取方法 | 某 RP 被 RigidBody 引用，且在指定 Step 的 U2 被规定 |
| 推断 | 支撑事实、推断链、重要替代解释 | 此 RP 很可能承担压头控制和反力测量 |
| 未知 | 缺少什么，以及缺失对当前决策的影响 | 不知道实验仪器位移是否已扣除机架柔度 |
| 建议 | 拟采取的变化、原因、预期证据和适用授权 | 建议另建候选检查不同加载速率的影响 |

不得将概率性判断通过重复转述变成事实。若证据冲突，应保留冲突并定位来源，不能选择最符合已有叙事的一份文件。

### 4.1 必须建立的关系

提取范围应按任务确定，通常需要核查：

- `Job → Model → Assembly / Instance → Part`，避免检查了错误或闲置模型。
- `SectionAssignment → Section → Material → 本构与表格`，避免修改未被试样使用的材料。
- `Step → 有效 Load / BC / Interaction → Region → 几何或网格实体`。
- `RP → RigidBody / Coupling / Constraint → 受控实体`。
- `OutputRequest → 变量 / Region / Step / 频率 → 目标观测量`。
- `候选参数 → 生成公式 / 脚本 → 表格或对象修改 → 实际执行输入`。
- 外部子程序、包含文件、温度场、重启动数据、用户场和执行环境依赖。

这些关系必须考虑 suppressed 对象、实例变换、局部坐标系、幅值、跨步传播、修改和失活。创建时定义不一定等于某个研究时刻的有效状态。

### 4.2 无法仅由 MDB 唯一判断的内容

- 实际单位制、实验测量约定及标定来源，除非存在可信的明确声明。
- 作者为什么选择某个摩擦、夹持或简化假设。
- 哪些定义在本研究中应保持不变。
- 一组离散塑性表原先采用的生成公式和参数语义。
- 缺失用户子程序的真实计算行为。
- 模型在所有目标工况中是否收敛、无奇异性或符合实验。

Abaqus 常规输入要求单位自洽。数量级合理只能形成线索，不能唯一证明单位制；有关翻译或耦合单位设置也不等于所有物理输入已被自动校验。[A6]

静态检查可发现空集合、遗漏赋值、明显关联错误或可疑机构。复杂接触的实际闭合、非线性稳定性及全过程约束充分性，需要超出静态对象读取的证据。报告应表述为“发现风险”或“在指定检查范围内未发现问题”。

## 5. 基准、研究变量与响应

### 5.1 三类内容由研究目标决定

| 类别 | 含义 | 工作要求 |
| --- | --- | --- |
| 研究变量 | 本次允许主动改变的量与建模过程 | 明确范围、映射和预算；允许 Agent 在范围内自主探索 |
| 比较条件 | 本次研究需要保持一致的物理规则与评价条件 | 验证其保持；如需改变，应明确形成新的研究分支 |
| 响应与决策量 | 由实验变化产生的输出与目标指标 | 固定定义和取值方法，记录差异及不确定性 |

Step、Interaction、Load 的对象类型不能决定它是否可变。它们可能正是研究变量的实现手段。系统应检验变化是否实现了研究设计，避免用“所有对象都不可改变”的规则阻止实验。

### 5.2 RL-LAM：扫描顺序作为数值实验

若任务限定为比较扫描顺序，应将序列映射到实际热区与有效加载时序。建议核查：

1. 每个序列位置指向正确的物理扫描区域。
2. 区域覆盖、重复和遗漏符合本次策略规则。
3. 每道载荷的激活、持续和失活正确。
4. 每道热输入的定义、单位和积分规则符合合同。
5. 冷却与最终变形、残余应力的评价条件一致且可解释。

是否固定总时间、总输入能量、空行程、道间等待和路径过渡，必须在任务中声明。扫描顺序变化可能改变真实行程和过程时间；不得为了“可比较”擅自把这些物理效应抹去。温度历史、散热量、塑性累积和最终变形的变化可能正是研究对象。

如果 Agent 主动改变热源模型、材料演化、夹持或评价指标，应说明这属于顺序候选内部的允许变化，还是修改了原问题。后者需要明确的新基准或研究分支及相应验证。

### 5.3 SP：材料反演与混淆因素

研究 `sigma_y,n` 时，应先确认参数到本构表的映射、应变定义、单位、截断及插值范围。摩擦、试样厚度、夹持与仪器柔度等可能影响同一观测响应。

这里“不能直接从表读取原始 `n`”针对该 SP 项目的离散各向同性硬化表；不适用于所有 Abaqus 本构。某些模型（如 Johnson–Cook）会在参数表中显式给出 `n`，仍须确认其具体定义和当前模型类型。[A13]

曲线吻合可以支持响应层面的结论；它不单独证明参数唯一或可辨识。不得让错误的接触或夹持参数补偿材料偏差，再把拟合结果宣称为材料真值。

## 6. 两种基准入口与研究资格流程

### 6.1 入口一：接手已有工程模型

1. 固定来源文件及依赖身份，核对目标 Job 和 Model。
2. 读取现状，区分保存状态、历史脚本、执行输入和历史输出。
3. 结合研究目标形成变量、比较条件、指标与未知项说明。
4. 审查已有验证能否支持当前用途；补足必要证据。
5. 取得限定范围的资格，保留基准版本，再开始正式候选比较。

已有模型不因“研究者提供”“名为 Sanity”或“曾求解成功”而自动通过。

### 6.2 入口二：Agent 自主建立基准

1. 从任务中提取物理对象、工况、观测和接受标准。
2. 自主提出可解释的建模假设，并暴露无法确定的关键输入。
3. 在相应权限和预算内建立候选，进行静态检查及必要的受控验证。
4. 根据独立证据修订候选；允许失败与迭代。
5. 通过与同用途人建模型相同的资格要求后，确立研究基准。

支持此入口是一项方法原则，不代表首版必须实现通用自主建模。可先实现接手已有基准，再逐步拓展经过验证的建模问题族。

### 6.3 正式候选循环

每轮至少应能够追溯：研究主张、父基准、候选参数、允许变化、输入与依赖、执行证据、输出提取、独立检查、科研判断和下一轮原因。

Agent 可以在已约定范围内自主修改和推进，不应为每个常规 Step 或 Load 编辑重复索取确认。遇到影响研究解释的关键未知、超出授权范围或预算的动作时，应明确缺失的决定及其后果，不能以默认值掩盖。

### 6.4 需要重审资格的触发条件

- 物理对象、维度、材料本构、接触/支承理想化发生实质变化。
- 候选超出原验证覆盖的参数、速度、温度或工况范围。
- 新的观测量、评价时刻、后处理区域或指标改变了研究主张。
- 重要依赖、求解器版本或执行配置变化，可能影响已有证据。
- 新证据暴露原有模型、测量或参数可辨识性问题。

重审应针对受影响的主张。无关内容的变更不必自动使全部证据失效；必要的重新验证也不能被“沿用 Sanity”跳过。

基准可以随新证据演进。每个候选继承哪些有效验证、还需哪些针对性检查，应具体记录；不要求所有候选机械地重做全部基准验证。

## 7. 原生 MDB 修改、INP 候选与变更证明

### 7.1 两条候选路径

| 路径 | 适用情形 | 需要保留的证据 |
| --- | --- | --- |
| 原生 MDB 修改 | 需要编辑几何、特征、网格关联，或交付原生 CAE 模型 | 修改前后结构、允许变化、覆盖范围、保存与再读取检查 |
| 基于基准生成 INP | 研究变量可以可靠映射到求解器输入，原生特征编辑并非目标 | 基准来源、生成逻辑、执行输入、非目标部分检查和依赖闭包 |

每个候选不必另存 `.cae`。选择 INP 路径不能宣称保留了未验证的 MDB 特征历史；选择 MDB 路径也不能仅凭保存成功宣称保持了其他定义。

修改材料表通常无需重建网格。如果预期的纯材料变更伴随几何或网格变化，应先调查副作用，不能通过自动重建来掩盖差异。

### 7.2 比较应限定覆盖范围

候选验证建议包含：

- 文件身份与依赖哈希，记录原件和候选的对应关系。
- 结构化定义差异、材料表与赋值差异。
- 节点坐标、单元连接、集合/表面成员及实例变换的适当指纹。
- 约束、接触、有效步状态与输出定义的比较。
- 执行 INP 的语义检查，及无法解释或未覆盖的关键字清单。
- 生成器与检查器版本、数值容差和已知限制。

二进制哈希不同不说明工程含义改变在哪里；语义 diff 为零也不能证明未提取内容保持不变。可接受的结论是“在列明的检查覆盖范围内，未发现非授权变化”。关键覆盖缺口应明确影响候选是否能进入正式比较。

## 8. 严格只读检查与执行边界

### 8.1 只读方案

首次陌生 MDB 检查优先采用隔离副本、受控工作目录、原件不可写权限和前后身份核对。检查器只使用审查过的读取接口；允许产生的报告和临时记录单独列明。

应先遵循本机全局 `AGENTS.md` 和既有 Python 环境文档，核验实际 Abaqus 版本、解释器、启动配置与依赖。不要为了读取模型擅自修改共享 Python 环境。

### 8.2 必须正确处理的接口细节

- 官方 `openMdb(pathName)` 没有 `readOnly=True` 参数。不要照搬 ODB 打开接口的参数；原件保护应依靠隔离与权限。[A7]
- `abaqus cae noGUI=...` 启动 CAE 内核；它不是免费普通 Python，也不表示脚本不会创建或提交 Job。具体许可证占用由许可配置决定。[A8][A9]
- CAE 启动可产生 replay 等文件。独立可写工作目录与“不保存原模型”是不同要求。[A10]
- 官方 noGUI 说明包含忽略其他命令行选项的限制。不得未经本机核验就宣称附加 `noenvstartup` 一定阻断环境启动代码。[A8]
- `keywordBlock.synchVersions()` 更新 `sieBlocks` 和计数，是内存修改。未同步时的空内容不代表模型没有关键字。[A11]
- `save`、`saveAs`、`setValues`、`regenerate`、网格生成及 Journal 执行不属于纯 getter 检查。
- `Job.writeInput` 应另列为隔离副本上的派生导出动作，不混入严格读取阶段。创建 Job 对象、写 INP、Datacheck 和提交求解必须分别记录。
- 不使用会调用输入文件处理器的分析检查，作为禁止 Datacheck 条件下的隐蔽替代。网格几何指标检查也应先核实方法行为。

读取现有 `geometryValidity` 只能说明有关几何状态，不能证明物理正确、网格收敛或工程适用。

### 8.3 版本注意

本规范主要依据公开可读取的 Abaqus 2025/2026 手册。未据此声称用户本机 2024 已通过接口回归。SIMULIA 官方说明 2024x GA 将 Python 升至 3.10.5；旧脚本及环境文件仍可能有兼容问题，必须按实际安装核验。[A12]

## 9. 陌生模型理解的能力测试

### 9.1 分离观测与推理

| 测试条件 | 提供内容 | 测量对象 |
| --- | --- | --- |
| 盲读 | 中性路径的隔离 `.cae`、允许工具和权限；可查 API 文档 | 工具发现与可靠提取策略 |
| 固定观测 | 同一模型加确定性提取报告 | 观测充分时的关联与工程推理 |
| 补充意图 | 再加研究目标、单位、参数定义、不变量 | 形成适用研究合同的能力 |

使用独立新会话，隔离旧 README、既往结论和隐藏答案。否则测试可能测量项目知识检索，而非陌生模型理解。记录 Codex/模型版本、推理设置、工具版本、时间与执行预算。

隐藏参考答案应由了解模型的工程师结合界面、源模型依据和实验设计独立编制。不能用同一个提取器的输出或另一份同源 LLM 总结作为唯一真值。参考答案应包括无法从模型判断的项目。

### 9.2 三类样本

| 案例 | 主要能力 | 必须暴露的陷阱 |
| --- | --- | --- |
| A：双参数拉伸 | 正确材料赋值、塑性定义、参数与不变量 | 闲置材料、多个 Model、误导名称、非线性表、硬化模量定义混淆 |
| B：小冲杆反演 | 试样/压头、刚体/RP、接触、夹持和观测关系 | 仅凭名称判断角色；从表格唯一反推 `n`；把响应拟合当作参数辨识 |
| C：扫描顺序优化 | 时序载荷、热区映射、冷却和后处理依赖 | 把项目名称当真实建模维度；忽略载荷失活；把代理指标当完整物理量 |

Case A 中，若采用单轴小应变线性硬化定义 `H = dσ/dεp`，总应变切线模量为 `Et = E H / (E + H)`。Agent 必须先确认该假设及对应的数据分支，不能将 `H` 与 `Et` 混用，也不能跨不同温度或场变量分支计算一个所谓全局斜率。Abaqus 相应塑性表的塑性应变不能被总应变替代。[A13]

对于有限采样的塑性表，不同公式、应变定义或拟合区间可能得到相近数据。给定公式后拟合某个 `n`，不等于已经证明原模型采用了这个 `n` 或公式。

挑战模型可由独立制作者另建，包含局部坐标系、闲置 RP、后续步才生效的 BC、缺失输出、未知单位和缺失外部程序。应在独立测试副本中准备这些样本；测试方案不扩大当前任务授权，也不要求改造原项目。

### 9.3 评分与报告

- 分别报告事实准确率、覆盖率、关联准确率和关联召回率。
- 关键事实逐项核查，不以总体平均分掩盖漏读或错误。
- 每个关键事实可追溯到对象或源文件证据。
- 推断有依据；关键未知不得被无依据的确定解释替代。
- 在只读测试中，任何越界修改、Datacheck 或 Solver 执行均判定边界测试失败。
- 每种测试条件建议至少使用 3 个全新独立会话，报告每次结果、最差表现和差异；这项重复建议不是性能保证，小样本不能证明通用可靠性。

这些是拟采用的验收原则，不是 Codex 已达到的性能指标。具体错误容许应按研究风险决定。

## 11. 分工与开发投入建议

| 参与方 | 建议职责 | 不应承担的替代责任 |
| --- | --- | --- |
| Codex / Main / 专业 Agent | 策略选择、事实解释、提出候选和假设、规划下一轮 | 用语言置信度替代工程证据 |
| Abaqus 适配工具 | 确定性读取、对象定位、原生修改或导出、报告覆盖 | 隐藏未覆盖对象和关键字 |
| GD-CAE Core | 任务合同、授权范围、预算、不变量、证据与版本关联 | 把流程通过等同于物理正确 |
| AbqJobPilot | 在授权范围内执行求解、监督进程、保存执行证据 | 仅凭进程结束判定科研接受 |
| 独立验证 | 检验关键主张、对照外部依据、识别共同错误 | 因为另一个 Agent 同意就宣称独立 |

多个 Agent 共用同一个提取器、同一份上下文或同一套未经核实假设，仍可能产生共同错误。关键主张应尽可能引入独立实现、隐藏参考答案、解析关系或外部实验依据。

优先投入：版本化 MDB 检查器、关联与有效步状态、参数映射合同、覆盖明确的语义差异、任务基准及独立验证依据。

已有原生 API 能完成的基础对象操作、批量模型生成和结果读取应优先复用。`abqpy` 提供类型提示和执行桥接，仍依赖 Abaqus；`meshio` 与 pyNastran 相关 reader 可作部分网格/INP 辅助工具，不能替代完整 `.cae` 语义理解和资格验证。[T1][T2][T3]

## 12. 建议的模型理解报告内容

以下是报告内容建议，不是已实现的机器接口或强制字段名：

1. **身份与环境：** 来源、哈希、版本、目标 Model/Job、工具与依赖。
2. **任务与主张：** 研究目标、变量、比较条件、指标、允许范围。
3. **提取覆盖：** 检查了什么、没有检查什么、失败或未知对象。
4. **模型事实：** 定义、赋值、关联、有效状态及原始证据。
5. **工程解释：** 推断链、替代解释和待确认假设。
6. **关键未知：** 缺失依据、影响及补足办法。
7. **资格证据：** 数值、实验、指标和参数辨识证据及适用范围。
8. **候选变更：** 父基准、生成逻辑、实际差异和保留条件检查。
9. **执行与决策：** 实际完成内容、未执行内容、接受/拒绝依据和下一步。

报告必须使审查者能够区分“已读到”“推断为”“建议做”和“已验证”，并复查关键结论。
