# Sanity Model：GD-CAE 的研究基准与使用指南

**面向读者：**使用 GD-CAE 开展工程仿真研究的研究者、工程师与项目负责人。  
**文档日期：**2026-11-04。  
**文档性质：**本文说明 GD-CAE 拟采用的研究原则与使用边界，不代表所有功能已在当前插件版本实现。本文中的 Sanity Model 是项目约定的术语，不声称是 CAE 行业的统一标准。

Agent 的详细检查、能力分级和执行规则见配套文档：[Agent 模型理解与 Sanity Model 协议](../architecture/AGENT_MODEL_UNDERSTANDING_AND_SANITY_PROTOCOL.md)。

当前候选可比较已有小冲杆历史 INP 和公开曲线，也支持在明确启用科研约定的新项目中查看、提议及确认修订。自建基准与真实求解仍属于产品方向。对某个基准的科研确认与对具体求解的执行授权分别记录。

## 1. 什么是 Sanity Model

在 GD-CAE 中，**Sanity Model 是针对明确研究任务建立、经过相应检查和验证、可以作为后续数值实验起点的工程基准模型。**

它使研究者与 Agent 面对同一个具体工程对象：零件在哪里，材料赋给了哪些区域，接触和支承作用于哪些实体，载荷如何随时间施加，结果从哪里提取。这些内容能够检查、引用和比较。

一个可用的基准应包含三类信息：

| 信息 | 应回答的问题 | 例子 |
| --- | --- | --- |
| 具体模型 | 当前计算的工程对象是什么？ | 几何、装配、网格、材料、约束、接触、分析步与输出 |
| 研究约定 | 要回答什么问题，什么可以改变？ | 优化扫描顺序；保持材料、每道热输入规则和支承条件一致 |
| 验证依据与范围 | 凭什么相信它适合这项研究？ | 理论基准、实验数据、独立检查、误差限、适用条件和未解决问题 |

一份已有 `.cae` 可以提供大量具体定义，但文件存在、能够打开或曾经算成功，都不足以单独证明它已经取得研究资格。

Sanity Model 也不必是一个极简演示模型。它应保留研究结论所依赖的关键物理过程；简化到失去这些过程，即使容易求解，也不适合承担该任务。一个复杂项目可以同时使用小型验证算例和项目基准，分别检验局部机制与整体研究设置。

## 2. 为什么它是正式研究的起点

自然语言适合表达研究目标、解释假设和讨论方案。复杂几何、装配关系、区域选择及随时间变化的条件，需要具体的工程表示承载。研究者与 Agent 只有对这些定义达成可检查的一致，才能判断后续变化究竟来自研究变量，还是来自模型被意外改变。

Sanity Model 提供以下基础：

1. **明确研究对象。**后续讨论可以定位到具体零件、材料、面、集合和分析步。
2. **建立比较条件。**候选结果之间的差异有共同参照，不必每次猜测是否更换了网格、支承或评价方法。
3. **约束研究变量。**Agent 可以主动探索，同时知道哪些变化属于本轮实验设计。
4. **保留证据。**能够追查某次结果来自哪个基准、哪些修改及哪些依赖。
5. **识别资格失效。**当新的假设超出原有验证范围时，可以开展针对性复核。

这里的“起点”指进入正式、可比较的研究循环所需的起点。需求澄清、候选建模、工具检查和验证实验可以发生在基准确立之前。一个尚未合格的候选，也可以用于明确标注的探索或资格验证，不能提前用它支持已被接受的科研结论。

## 3. 谁来建立基准

GD-CAE 应允许两种入口：

| 入口 | 工作方式 | 取得基准资格的条件 |
| --- | --- | --- |
| 接手已有模型 | 研究者提供模型及可用的研究资料，Agent 检查定义、依赖与适用范围 | 对当前任务有足够的检查和验证证据 |
| Agent 自主建立 | 研究者提供目标和已有数据，Agent 建立候选，再组织相应验证 | 与人工建立模型适用相同的证据要求 |

**人工预制 `.cae` 不应成为所有任务的强制入口。**模型由谁创建，不决定它是否可靠。Agent 自建模型通过独立验证后，可以成为后续研究的基准；人工模型中存在的关键未知，也必须如实保留。

自主建立和验证基准可以分阶段开发。保留这条能力路径，不意味着首个插件版本必须已经完成它；各版本应明确告知实际支持的入口。

## 4. 需要区分的四种对象

| 对象 | 含义 | 可以支持的结论 |
| --- | --- | --- |
| 候选模型 | 已建立或已接收，资格检查尚未完成的模型 | 描述定义、提出问题和开展约定的探索 |
| 研究基准 | 对指定任务、范围和接受标准已有相应证据的模型 | 在其资格范围内组织正式数值实验 |
| 实验候选 | 从研究基准产生，改变约定研究变量的模型或求解输入 | 检验候选方案；结果仍需检查和评价 |
| 基准修订 | 改变原基准的重要假设、结构或比较条件的新版本 | 经相关复核后，成为后续研究的新参照 |

研究基准具有版本和范围。它不意味着永远正确，也不意味着由它派生的所有候选自动合格。某个候选求解失败，不会自动否定基准；某次求解成功，也不会自动确认候选的科学价值。

## 5. Agent 可以主动改变什么

改变物理条件本身就是数值实验的一部分。GD-CAE 应根据研究目标区分研究变量、比较条件和观测结果。

| 类别 | 含义 | 处理原则 |
| --- | --- | --- |
| 研究变量 | 本轮主动改变的因素 | 在约定范围内允许 Agent 自主设计 |
| 比较条件 | 为解释候选差异而保持一致的条件 | 明确记录并检查；变化时说明原因和影响 |
| 观测结果 | 数值实验产生的响应 | 按一致的评价定义提取和比较 |

这些类别取决于任务。同一个摩擦系数，在材料反演中可能是需要固定或独立约束的条件，在接触研究中则可以是研究变量。模型中“已经存在”某个条件，不表示它天然不可改变。

### 5.1 RL-LAM：扫描顺序研究

对于比较 `[1, 2, 3, 4, …]` 与 `[7, 9, 2, 4, …]` 等扫描顺序的任务，Step 顺序及各热区的载荷激活时序可以变化。不同温度历程和最终变形正是需要观察的响应。

应检查的是候选是否正确实现了研究变量：每个热区按计划激活、旧载荷按规则失活、没有漏道或重复加热，以及冷却和结果评价条件是否具有约定的可比性。具体哪些热输入、支承、路径转换时间等条件保持一致，应由研究设计明确，不能由文件名称推断。

若研究同时允许改变扫描速度、功率或停留时间，就应将它们加入变量范围，并相应更新比较和验证要求。

### 5.2 SP-InvOpt：材料参数反演

对于 `sigma_y` 和 `n` 的反演，应明确它们对应的本构公式、应力应变定义、单位和材料表生成方式。读取一张塑性表，不一定能唯一恢复其原始参数化公式。

几何、夹持、摩擦和结果提取方式会影响参数判断。若多个参数或假设可以互相补偿，力—位移曲线吻合仍不足以证明反演材料参数唯一且正确。应通过独立依据约束关键条件，或明确报告可辨识性和不确定性。

## 6. 修改边界与自主性

基准应保留为可追溯的参照，候选在独立版本上产生。Agent 可以在已有研究约定、资源预算与执行权限内连续推进，不需要对每个 Step 或 Load 的例行修改逐次征求确认。

若要改变约定之外的重要假设，Agent 应明确提出新的研究方案及证据需求，并按当前授权范围处理。需要新的决定时，应指出具体缺少的决定；不得把所有不确定性都变成暂停理由。

重新验证应针对实际影响。例如：修改输出频率主要影响观测；改变加载速率可能影响准静态假设；改变夹持会影响力的传递路径；改变几何或网格可能影响离散误差。复核范围应与变化相称，不必机械地从头重做所有检查。

探索性候选允许失败。失败应保留为研究证据，并与已接受结果分开记录。系统应阻止的是把失败、未验证或证据不足的结果表述为可靠结论。

## 7. 基准需要验证到什么程度

资格验证应回答：**现有证据是否足以支持这项指定的研究用途？**

| 检查或验证 | 能提供的证据 | 不能单独证明的内容 |
| --- | --- | --- |
| 文件与对象检查 | 模型可访问、目标对象和关联明确、依赖已识别 | 物理假设正确 |
| 结构和量纲检查 | 发现缺项、明显冲突及部分单位问题 | 复杂非线性全过程稳定 |
| 成功完成求解 | 此次设置在此次环境完成了计算 | 模型代表真实对象，或结果足够准确 |
| 理论或简化基准对照 | 检验特定机制、实现或极限情况 | 所有复杂工况都适用 |
| 网格与时间离散研究 | 估计特定结果对离散设置的敏感性 | 本构与边界条件符合实际 |
| 实验或独立结果对照 | 检验指定观测量及适用条件 | 所有参数唯一可辨识，或范围外预测可靠 |

不要求每个任务机械地执行全部项目。应选择能检验主要风险和研究主张的证据，并记录尚未解决的问题、接受标准和适用范围。

独立验证需要有独立依据，例如解析解、实验、不同实现或单独核对的参考答案。让两个 Agent 阅读相同资料后得出相同结论，不能自动排除共同错误。

## 8. 必须提供 `.cae` 吗

不必须。应选择能承载任务所需信息、能够检查来源和变化的模型表示。

| 表示 | 适合的用途 | 使用边界 |
| --- | --- | --- |
| 原生 `.cae` | 保留和编辑原生几何、特征、装配及模型对象 | 需要相应 Abaqus/CAE 访问能力；外部依赖仍须识别 |
| `.inp` 及其依赖 | 承载求解定义，适合许多材料或工况候选生成任务 | 不能当作原生 MDB 的无损归档或几何特征重建来源 |
| 建模脚本及输入数据 | 重建、参数化和追踪模型生成过程 | 脚本可执行不代表模型已经验证 |
| `.odb` 及执行证据 | 检查已保存的计算结果及部分模型信息 | 不能替代原始建模假设和完整依赖 |

对于只改变扫描顺序或材料表的研究，生成候选 INP 可以是合理路径。应证明候选来自哪个基准、实现哪个变量组合，以及哪些比较条件得到保留；没有必要仅为形式完整而要求每个候选都另存 `.cae`。

当任务需要编辑原生几何或特征时，应采用能够保留这些信息的工作路径。Abaqus 官方明确指出，输入文件无法存储 MDB 的全部数据，导回时 Parts 主要以网格形式恢复。[R1][R2]

## 9. Codex 能理解模型到什么程度

Codex 可以利用文件、Shell 和外部工具工作；Abaqus API 则提供模型对象的读取与修改机制。两者结合，能够获得比阅读文件名称或说明文档更具体的证据。[R3][R4]

以下等级用于区分能力，不是 Codex 已达到的通用准确率，也不是当前 GD-CAE 版本的功能承诺：

| 等级 | 能力 | 使用时应关注什么 |
| --- | --- | --- |
| L0 文件识别 | 确认文件及来源线索 | 是否识别了正确文件和版本 |
| L1 定义读取 | 读取对象和属性 | 关键对象是否漏读，值是否准确 |
| L2 关系重建 | 找到赋值、约束、接触、步状态和输出关系 | 是否真正关联到目标工程对象 |
| L3 工程解释 | 解释角色、假设、参数和研究含义 | 哪些是事实，哪些只是推断 |
| L4 受控修改 | 生成候选并检查约定不变量 | 是否有可追溯的变更证据 |
| L5 科研适用性验证 | 检验模型是否支持指定研究推断 | 是否具有独立依据及明确适用范围 |

给出一份复杂 `.cae`，不能直接假定已经达到 L3 至 L5。没有 Abaqus 时，已有 INP、脚本和报告仍可提供大量信息；只给一个二进制 `.cae`，可靠内部读取则受到明显限制。配套协议说明如何区分读取事实、工程推断和需要独立验证的结论。

## 10. 如何开始一个任务

已有模型时，建议提供：

- 研究目标与主要评价量。
- 模型位置及希望使用的 Model、Job 或版本；不清楚时可以明确说明。
- 已知单位、本构定义、外部子程序或数据。
- 已有验证证据及你知道的限制。
- 希望探索的变量、需要保持的比较条件和资源预算。

信息不完整时，Agent 应先检查能够获取的事实，再提出具体缺项。研究者不需要事先用自然语言重述全部模型细节。

没有现成模型时，建议提供目标、几何与材料资料、可用验证数据及主要假设。Agent 可以先提出和建立候选，再说明确立基准还需要什么证据。

使用中应能够得到五个直接答案：当前基准是什么；它对什么任务合格；本轮允许改变什么；结果依据是什么；还有哪些问题无法确定。
